React interview questions with explained answers

By InterviewCrack · Updated 17 October 2026

Prepare for a React interview by explaining how data changes the UI, then applying that explanation to a small example. These questions focus on props, state, list identity, effects, and rendering rather than memorised definitions.

1. What is the difference between props and state?

Props are inputs a component receives. State is memory managed by a component. A state setter requests another render; changing an ordinary local variable does not preserve a value across renders or request an update.

Try it: Describe a counter with a step prop and a count state value. Which component should own the count if two sibling controls both change it?

2. Why can reading state immediately after setting it show the old value?

An event handler sees the state snapshot for its render. Calling a setter schedules an update; it does not change that snapshot. When the next value depends on the previous value, a functional updater such as setCount(c => c + 1) expresses that dependency.

Try it: Explain why three functional increments can behave differently from three calls to setCount(count + 1) in the same handler.

3. Why do list items need stable keys?

Keys let React match items between renders. Use a stable identifier from the data. An array index can associate the wrong component state with an item when a list is reordered, inserted into, or filtered. A random key generated during rendering changes identity every time.

Try it: Imagine a sortable list of editable tasks. Explain what could happen to an unfinished edit if every row uses its array position as a key.

4. When should I use an effect?

Use an effect to synchronise with a system outside React, such as a subscription or browser API. A value that can be calculated from current props and state usually belongs in rendering. A user-triggered action usually belongs in its event handler.

Try it: For a window event listener, describe how setup adds the listener and cleanup removes the same listener. Explain which changing values the effect depends on.

5. Does a render always change the DOM?

No. Rendering calculates the UI. React then commits necessary changes. A component may render while the resulting DOM remains unchanged. Diagnose a slow interaction by measuring where time goes before adding memoisation.

Try it: Describe how you would investigate a slow searchable list: reproduce the interaction, profile it, identify expensive work, make one change, and measure again.
